# 聊天 app（`@palace/chat`）

> 总览见 [docs/ARCHITECTURE.md](../../docs/ARCHITECTURE.md)。测试见 [TESTS.md](TESTS.md)。

## 职责

一个类 Slack 的聊天系统：账号、频道、私信、讨论串、消息、附件、消息上的任务、已读位置，以及给人类账号的推送和实时视图。

聊天 app 不知道 runtime、run 和模型。在它眼里 Agent 只是一种账号。谁能登录、谁是管理员由 Web 外壳管理。

## 概念

- **账号**：人或 Agent 在聊天里的身份。种类（`kind`）是 `human` 或 `agent`，创建时定下，之后不变。可以有多个人类账号，各有自己的已读位置、未读摘要和推送订阅。
- **会话**：频道（公开或私有）或私信。
- **时间线**：一串按顺序编号的条目。每个会话的顶层是一条时间线，每个讨论串也是一条。条目在所属时间线内有只增不减的序号。
- **已读位置**：每个账号在每条时间线上一个序号，表示这个账号已经看到这里。这是聊天 app 记录"谁看过什么"的唯一方式。
- **收件事件**：消息提交时，聊天 app 在同一个事务里为每个应被通知的账号追加一条收件事件。事件 ID 全局递增，并标明是否提及、是否私信、是否讨论串。
- **实时事件**：人类客户端实时显示所依靠的全局日志。每条记录一个变化（新条目、会话或成员、账号、某个人类的已读位置），并带受众：空表示所有人类都看到，否则只有那个账号看到。`chat.sqlite` 的触发器在改动事实的同一个事务里追加事件，所以没有一条写路径能改了显示的内容却不留事件。

## 谁会被通知

- 频道顶层消息通知频道所有成员，作者除外。
- 讨论串回复只通知关注这个讨论串、并且还能读这个会话的账号。关注者是根消息作者、回复过的人和在讨论串里被 @ 过的人（包括这条回复 @ 的人）。
- 私信通知对方。
- 人类账号能读所有会话，但同样只在上面这些情况下收到通知，没加入的频道里的顶层消息不通知它。
- 不做静音。

"谁关注哪条时间线"只在 `followed_timelines` 视图里定义一次，收件事件和未读摘要都从它查，所以两者不会不一致。"谁能读哪个会话"同样只在 `readable_conversations` 视图里定义。

## 接口

所有操作都以某个账号的身份调用，人（经 Web 外壳）和 Agent（经聊天工具）用同一套接口。实际签名和 Zod 契约在 `src/index.ts` 与 `@palace/chat/contracts`。

| 调用方 | 操作 |
| --- | --- |
| 人和 Agent | `readUnread`、`readHistory`、`search`、`send`、任务操作、`join`、`leave`、`openDm`、`invite` |
| 连接器 | `inboxEvents(account, { after })` 读收件事件；`watchInbox` 在提交后通知哪些账号有了新事件；`unreadSummary` 给出渲染通知需要的一切 |
| Agent Manager | `ensureAccount`（以 `externalId` 幂等）、`findAccount`、`deactivateAccount`（永久）；`forAccount(account)` 返回绑定账号的读写方法，结构上满足 runtime 的聊天端口 |
| Web 外壳 | `findHuman(handle)`、`listAccounts`、头像读写；人类专用的 `liveSnapshot`、`liveEvents`、`watchLive`、`subscribePush`、`unsubscribePush`，Agent 账号调用得到 `human-only` |

`watchInbox` 和 `watchLive` 只在事务提交后触发。回滚、被拦下的发送和按回执返回的重复调用都不触发，监听者抛错不影响写操作。

`liveSnapshot` 和它的游标在同一次读取中得到：之前提交的都在快照里，之后提交的都在 `liveEvents(cursor)` 里。快照带调用者自己的账号 ID、每个会话顶层最新的一条条目（用于会话列表排序和预览），以及可选的一条时间线的最新一页。

## 规则

1. **按序读，并说明跳过了什么。** `readUnread` 从已读位置开始。未读内容超过 `budget`（按字符数和附件大小算）时，返回最新的、刚好放得下的那些，并在结果里说明一共多少条、返回了哪段序号、跳过了哪段，以及跳过的部分里 @ 了读者的序号。已读位置推进到最新一条，读者知道自己跳过了什么。

2. **服务端在发送前检查读者是否错过了新消息。** `send` 比较时间线上别人发的最新条目和发送者的已读位置。有新条目时不发送，把这些条目放在结果里返回并推进已读位置，调用方可以修改后再发或原样再发。工具参数里不出现"我看到哪了"，服务端也不保存被拒绝的草稿，要发的内容本来就在模型的上下文里。新账号的已读位置从 0 开始，所以刚加入频道就发言会先收到最近的消息。

   这项检查是 `send` 的选项，由调用方的程序决定，不由模型决定。Agent 的聊天工具总是开启，且不向模型暴露这个选项。网页关闭它，因为人类一直看着屏幕，网页显示消息时推进人类的已读位置。

3. **每个写操作和每次 `readUnread` 按（账号，`requestId`）幂等。** 第一次的结果存为回执，重复调用原样返回，包括 `readUnread` 返回的那一页。所以崩溃后重做工具调用既不会重复发消息，也不会因为已读位置已推进而丢掉一页。Agent 的 `requestId` 是 Durable 的工具调用 ID，人类操作的 ID 由客户端生成。

4. **一条消息相关的一切在一个事务里提交**：消息、收件事件、推送队列、随消息创建的任务和实时事件。会被拒绝的请求（参数非法、@ 了不存在的账号、没有权限）在写入开始前被拒绝，写入过程中没有拒绝分支。

5. **消息不能编辑，也不能删除。**

6. **可见和可操作分开判断。** 公开频道不加入也能读，发言、建任务和上传附件都要求是成员。私有频道和私信只有成员能读。拥有任务不额外授予权限。

7. **任务挂在消息上**，一条消息可以有零到多个任务。创建和认领是两个动作，创建不会自动指派。任务的每次变化（创建、认领、让出、转交、完成）作为任务条目写进消息所在的时间线，和消息共用序号。所以读取能看到任务变化，规则 2 的检查也覆盖任务操作。任务条目不产生收件事件。已经不是主人的人迟到的"让出"不会撤销别人新的认领，只有当前主人能转交。

8. **推送只给人类账号，每个订阅只推它自己账号的通知。**
   - 推送是通知的一部分。一条消息推给某个订阅，当且仅当它通知了订阅所属的账号，是给该账号的私信或 @ 了该账号，且该账号仍然有效。提及只来自 `send` 的 `mentions`（账号 ID），正文里的 `@` 文字不算。
   - 消息提交的同一个事务里为每个匹配的订阅追加待投递记录。
   - 投递循环按到期时间逐条经调用方给的 `PushSender` 发出。回答失效时删除订阅和它的队列；暂时失败 30 秒后重试，每次翻倍，失败 10 次放弃；拒绝时丢弃这条、保留订阅。重试计划存在队列里，重启后照常继续。发送前再查一次账号是否有效。投递只改推送队列和订阅，不影响已提交的消息。`PushSender` 必须在有限时间内返回，因为投递是串行的。
   - 推送内容不含消息正文，只有定位和显示需要的字段和一个 `tag`。同一条消息的每次投递 tag 相同，重复投递只替换通知。
   - 订阅以浏览器 endpoint 或 APNs 环境加 token 为键。另一个账号或另一个原生 binding 订阅同一个键时，删除旧订阅和它的队列再新增。原生取消订阅要求账号和 binding 都匹配，所以旧的取消请求撤销不了新的登记。

9. **实时事件流只给人类账号。** 除已读位置外的事件对所有人类可见，已读位置事件只给前进的那个账号。读取按受众过滤，游标仍是全局位置，所以事件稀少的账号也会往前走。
   - 事件只记对象，内容在读取时现查。条目不可变，带全文；其他种类带对象现在的样子，所以旧的或重复的事件应用到客户端上结果相同。
   - 游标由纪元和事件 ID 组成，可直接作 SSE 事件 ID。纪元在新建 `chat.sqlite` 时随机生成，换了数据文件旧游标就作废。
   - 事件保留一天。游标纪元不对、早于保留范围、超前于库里最新事件或者格式不对时，`liveEvents` 回答 `resnapshot`，客户端重新拉快照。恢复旧备份只在库里的事件追上客户端游标之前能被发现，所以恢复备份后要让客户端重新加载。

## 头像

`account_avatars` 按账号保存一份 WebP 和它的 SHA-256 版本号，账号视图只带 `avatarVersion`。增、换、删图片的触发器在同一事务里追加账号实时事件，重复上传相同内容不产生新事件。

接口接受最多 320 KiB、每边 1 到 256px 的 PNG。sharp 限制像素数、完整解码，再编码为质量 80 的静态 WebP，不保留元数据。转换在事务外完成，随后在同步事务里检查账号有效，再提交图片、版本、事件和回执。不合规的输入被拒绝，旧头像不变。角色权限由外壳检查。

## 持久化

`data/chat.sqlite`：账号、会话、条目、已读位置、回执、收件事件、实时事件、头像、推送订阅和推送队列。结构版本记在 `PRAGMA user_version`，迁移列表在 `src/chat-migrations.ts`，迁移规则见总览的数据布局。
