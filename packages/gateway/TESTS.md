# Node 网关边界测试

> 这个模块的设计见同目录的 [ARCHITECTURE.md](ARCHITECTURE.md)。所有模块共用的测试规则和替身见 [docs/MODULE_TESTS.md](../../docs/MODULE_TESTS.md)。

**边界：** `NodeGateway` 接口，以及它对 node 说的 WebSocket 协议。

**替身：** 假 node、网络代理、可控时钟。

- 配对令牌只能用一次，过期后不能用；令牌只以哈希形式存储。
- 配对只新增 node：用有效令牌配对一个已配对的 node ID 被拒绝，原来的公钥照常认证，令牌没有被用掉。
- 已配对的 node 用签名认证；只有在控制面明确回答"不认识这个身份"之后，node 才会用配对令牌。
- 配对后 `nodes()` 和 `status()` 显示从 hostname 生成的名字、在线状态和完整系统信息。自动名字符合长度和字符规则，hostname 冲突、截断后冲突、全是非法字符时仍能配对，名字互不相同。
- 新格式重连更新整份系统信息和连接时间，保留管理员设定的名字；缺少 `system` 的旧配对和认证照常成功，认证保留以前的系统报告。
- `renameNode` 能改名，改成原名不改变状态；非法名字、名字被占用、不存在的 node 分别以 `invalid-input`、`name-taken`、`unknown-node` 拒绝，现有名字和系统报告不变。
- 从已发布版本生成的存储夹具包含已配对 node 和测试身份。新网关打开副本后，旧 node 得到 `node-<UUID 前 8 位>`，前缀冲突时加后缀，系统报告为空；旧私钥照常认证，夹具里未使用的令牌仍然能配对。
- 同一个 node 建立新连接后，旧连接被关闭，来自旧连接的消息一律被拒绝。
- `runTool` 把输出流式交给调用方，最后返回结果；`home`、`visit` 原样进入 `gateway.run.tool`。
- 两个 Agent 在同一个 node 上并发调用，各自拿到自己的输出和结果：网关为每次调用生成自己的请求 ID。
- 调用没有自己的期限：时钟推进很久之后，node 送来的真实结果照常交给调用方。
- 调用方中止调用：网关立即以"已停止"（不是"结果未知"）结束它，并让 node 停掉这一次调用；之后 node 送来的输出和结果被丢弃。
- Agent ID 不合法的调用在发送和注册任何东西之前就被拒绝。
- 工具调用进行中连接断开：调用立即以"结果未知"结束；之后即使假 node 重连并送来这次调用的结果，也被丢弃，不会交给调用方。
- node 离线时调用 `runTool`，立即返回"节点离线"，不排队等待。
- `browse` 把 Agent ID 和路径交给 node，原样返回 node 的回答，列表和拒绝都一样；Agent ID 或路径不合法时什么都不发。
- node 离线时 `browse` 立即回答 `node-offline`；回答之前连接断开，同样立即回答 `node-offline`，之后迟到的回答不算协议错误，被丢弃。
- 另一个 node 送来某次浏览的回答（同一个请求 ID），不会交给调用方，调用方继续等自己的 node。
- 黑洞连接（TCP 没断但收不到数据，node 仍在发心跳）在心跳超时后被判定离线。
- 未认证的连接数量和消息大小（按序列化后的帧计）有上限；超限、格式错误或顺序错误（认证前发别的消息、重复认证）的连接被关闭，之后它送来的消息一律不读。
- 握手超时以协议错误（`gateway.error`）结束连接，不是身份拒绝。
- 一个 node 断开，不影响其他 node 上的调用。
- node 注册表存在 `control.sqlite` 里，和别的模块的表共处：别的模块的表在、版本不同，网关照常打开，重启后已配对的 node 照常认证，别的模块的数据不受影响，数据目录里除了 `control.sqlite` 没有别的文件；别的模块开着读事务时，网关照常配对 node。
- 网关自己的表版本不对，或者别的模块已经占了它的表名，网关拒绝启动，抛出的 `ControlStoreIncompatible` 带着 `control.sqlite` 的路径；别的模块照常打开。
- 一个模块的迁移列表从 `[v1]` 变成 `[v1, v2]` 后，下一次打开就升级已有的表，原有的行保留，别的模块的行不受影响；新建的存储和升级来的存储结构一样。
- 新的迁移失败时，整个事务回滚，存储留在旧版本，旧列表照常能再打开它，拒绝启动抛出的 `ControlStoreIncompatible` 带着文件路径。
- 存储里的版本比模块的列表新时拒绝启动，不改动存储。
- `Migrations` 本身：空列表、版本不严格递增的列表构造时报错；`after` 对新存储给出全部迁移，对已是最新的存储给出空，对更新的或不在列表里的版本给出"无法到达"。（`packages/migrations/test`）

- 旧 node 未声明 `workspaceVisits: true` 时，访问准备和执行均被拒绝且不发消息，主 node 准备和执行仍可用。声明只属于当前认证连接，重连时不从历史系统信息继承；新连接降级为旧协议后再次拒绝访问。
