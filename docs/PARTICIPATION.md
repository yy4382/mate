# Participation and attention

A member chooses what to follow and where to participate. Discovery and membership are distinct from message visibility, submission gating, execution permission and budget attribution.

`conversations.capabilities` reports implemented controls, optionally for a known conversation. `conversations.list` returns current joined/internal spaces; an external failure preserves internal results and reports incomplete. `conversations.discover` returns one page of public metadata and a next cursor. Its `candidateId` is an opaque adapter reference, **not** a canonical conversation or permission token. Discovery does not create primary conversation bindings, so merely listing public channels cannot prevent an owner from later using one for an internal projection.

`conversations.join` accepts either a discovered candidateId or a known external conversationId. Slack joins require a non-archived public channel and the acting Agent's installation. A successful explicit join establishes canonical identity/access. `conversations.leave` accepts a known external conversationId and removes access after confirmed success. DMs and host-managed internal rooms return unsupported for membership controls; watch/mute/defer remain available. Private Slack channels require an invitation.

Join/leave are durable state-changing actions. Succeeded/failed receipts replay without another write; a timeout is unknown and blocks another membership write to that target. `conversations.refresh` reads current membership. Observing the requested state reconciles the unknown intent; the opposite observation leaves uncertainty intact because it cannot prove a delayed request will never take effect. Concurrent permission changes prevent stale HTTP responses from overwriting current access. Do not describe unknown as a successful join or leave.

Mute suppresses ordinary target activity. Personal Agent mentions and DMs pierce mute in both durable delivery and attention summaries. Defer explicitly postpones a target, including direct requests, without marking it read or handled. On expiry it produces one durable wakeup, subject to access and mute; muted targets with unresolved direct requests can still wake. Existing runs are not cancelled by either preference. System status receipts never become direct work requests merely because they are in a DM.

Slack contracts verified against official documentation on 2026-09-21: [join](https://docs.slack.dev/reference/methods/conversations.join/) uses `channels:join` for bot tokens; [leave](https://docs.slack.dev/reference/methods/conversations.leave/) requires the applicable channel write/manage scope and can report already absent; [list](https://docs.slack.dev/reference/methods/conversations.list/) is cursor-paginated and filtered to public channels here. Missing installation scopes are explicit failed receipts, not simulated success. Real workspace installation and protocol validation remain connection-time checks.
