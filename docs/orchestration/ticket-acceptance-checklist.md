# Orchestrator verification checklist: tickets #34–#53

Owner: orchestrator. Ticket implementers do not edit this file. This is the
evidence checklist the orchestrator uses to accept a ticket, so that "the
sub-agent said it passed" is never the basis for marking a ticket done.

## How a ticket is accepted

For ticket `#N`, all of the following must hold:

1. `LAND_SHA` exists on `codex/first-release-simplification` and `git show --stat
   $LAND_SHA` touches only areas the ticket owns.
2. `git log -1 --format=%B $LAND_SHA` references `#N`.
3. At `LAND_SHA`: `pnpm typecheck` exits 0 and `pnpm check` exits 0 with the
   full suite green (test count may legitimately shrink only where the ticket
   removes the tests of the behaviour it removes).
4. Each acceptance criterion below has a named command or test file that proves
   it, run by the orchestrator or already demonstrated in the sub-agent report.
5. No requirement was reworded to match what was built.

## Baselines that must not silently break

- Current-checkpoint create/verify/restore: `tests/daemon/checkpoint.test.ts`,
  `tests/deployment/linux-checkpoint.test.ts`.
- Restart and recovery: `tests/recovery/store.test.ts`,
  `tests/coordination/recovery.test.ts`, `tests/slack/history-recovery.test.ts`,
  `tests/daemon/integration.test.ts`.
- Deployability on Linux: `tests/deployment/linux-deployment.test.ts`,
  `tests/deployment/readiness.test.ts`, `tests/deployment/release.test.ts`.
- Architecture and dependency direction: `tests/contracts/architecture.test.ts`,
  `tests/contracts/dependencies.test.ts`, `tests/contracts/pi.test.ts`.
- Execution authorization boundary: `tests/policy/broker.test.ts`,
  `tests/policy/system-operations.test.ts`.

Expected to leave with their tickets (removal is the point, not a regression):
`tests/daemon/migration.test.ts`, `tests/conversations/canonical-migration.test.ts`,
`tests/reminders/migration.test.ts`, `tests/daemon/usage-upgrade.test.ts` — old
migration chain / old config-compatibility only. A ticket that removes one of
these must show the removed compatibility path is really gone, not just unlinked.
