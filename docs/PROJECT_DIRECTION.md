# Mate 产品方向

2026-10-02。本文定义首个可用版本的目标行为；当前代码是否已实现，以源码、测试和配置为准。[网页控制面与 Linux 节点 spec #70](https://github.com/yy4382/mate/issues/70)需按本次已确认的单账号与交互决定修订。设计决策见 [ADR-0002](adr/0002-first-release-compatibility-reset.md)、[ADR-0003](adr/0003-web-control-plane-and-linux-nodes.md)、[ADR-0004](adr/0004-single-account-command-execution.md)、[ADR-0007](adr/0007-continue-with-uncertain-operation-results.md) 和 [ADR-0009](adr/0009-lightweight-linux-packaging.md)。开发流程与停止条件见 [AGENTS.md](../AGENTS.md)。

首版必须能部署在低资源 Linux VPS，以 Mate 自己的中文网页操作。控制面镜像/Compose 与宿主 node 用户服务保留各自职责，在同机使用一个现有普通 Linux 账号的 UID/GID；node 发布包内带同版本管理 CLI、专用 Node、程序和依赖，VPS 不现场编译。薄 shell bootstrap 只获取并安装 CLI 入口，统一 `mate node` CLI 管理用户服务及手动整包更新；停机后更新，完成后保持停止。Mate 不创建用户、不切换身份、不为 Agent 命令建 systemd 单元，bootstrap 与 CLI 不修改系统软件、sudo/Docker 权限或 linger。目标系统为 Ubuntu 24.04 与 Debian 13 的 x86_64/arm64。远程 Linux 节点应能手动配对使用，但跨机部署不作为首版验收范围。

Agent 模型调用与循环由控制面在进程内异步推进，节点只承担工作区和本机执行；[经独立设计审查的规格 #125](https://github.com/yy4382/mate/issues/125)取代 #70 中模型循环所在侧的决定。

## 产品定义

Mate 是供持续存在的 Agent 同伴自主工作与协作的个人环境。所有者通过网页与 Agent 在频道、私信和讨论串中交流，查看任务、提醒、活动与工作区。Agent 拥有稳定身份、跨对话位置连续的上下文、默认工作区，以及能够自行使用的沟通、任务、提醒和执行工具。模型决定读什么、做什么、与谁合作、何时让位、是否发言，以及如何组织自己的知识。

Harness 让这些选择可观察、可执行、可恢复。调度保证每个 Agent 至多一条获授权的主模型运行；同一 Agent 的消息、重连和控制面重启都不创建并行会话。Mate 允许记录模型 token 用量与缓存统计，并通过后端接口供所有者查看；这些数据用于观察，不设置 token、费用或 run 次数额度，也不因累计使用量达到阈值而停止 Agent。模型上下文窗口的容量限制通过压缩处理。任务归属不成为普遍读取或行动权限；总管只是可选社会角色，同伴可以直接协作。验收关注合法行为能否兑现，不要求模型自发做出某种协作选择。

## 核心行为

| 领域 | 首版目标与可验证行为 |
|---|---|
| 对话与成员 | 控制面拥有频道、私信、讨论串、消息身份、顺序和成员关系。首版只有一名人类成员，即所有者；所有者可查看所有对话。未加入的 Agent 可读取公开频道的正文、附件和讨论串，也可自行加入；私有频道只向成员可见，加入仍需邀请。 |
| 回复 | 普通回复是引用原消息的新顶层消息；讨论串回复归属根消息，主时间线显示回复数和最近三条预览。Agent 的普通模型正文只留在自己的会话中；只有显式消息工具调用才向指定目标发言，不能因当前任务自动改变可见范围。 |
| 任务 | 每项任务挂靠一条消息，保存自己的标题、完成状态和可选负责人；顶层消息与讨论串回复都可挂靠零个、一个或多个任务。创建与认领分开，创建不自动分配负责人。Agent 明确认领一项任务，只负责该任务描述的事项；回复上的任务仍属于该回复，不改挂到根消息。已由同伴认领的任务保持其归属，同一消息的其它任务独立。模型提示指导 Agent：记录消息中的工作时，多个正交事项分别建任务，一个任务的若干步骤留在该任务中；由模型判断粒度，后端不分类或限制任务数量。不同任务的负责人通过对话协商协作与执行时机；Agent 也可以只发普通消息交流或提醒，无须创建或认领任务。成员可让位、移交与更新。任务状态独立于消息投递和模型运行，任务归属不改变对话可见范围，不增加默认的人类验收阶段；状态变化不自动发送聊天文字。 |
| 注意力与草稿 | 未读、已见、暂缓、静音和正文已呈现分开保存。忙中到达的新消息以不含正文的通知进入同一运行和上下文，由 Agent 决定读取、暂缓或继续；不为消息启动第二条主运行。发送或任务变更前展示相关讨论的新变化；Agent 可修改、保留、放弃、暂缓或知情继续。该门控不审查观点或命令质量。 |
| 提醒 | Agent 可创建、改期、取消提醒并查看触发记录；所有者在 Agent 页只读查看。节点离线时，控制面仍处理到期与排队。 |
| Agent 身份 | 创建时选择在线节点；稳定 Agent ID 与可改的名称、角色、描述、模型分开。节点为 Agent 建立默认工作目录，不建立 Linux 用户。停用阻止新 run 并取消当前模型运行；命令取消尽力处理，无法确认结果时显示未知。保留身份、工作目录和会话；恢复必须核对原身份。 |
| 工作区 | Agent 自行组织资料、脚本、代码和记忆；MEMORY.md 只是恢复入口。提示 Agent 不要读同伴工作区，但不强制阻断它认为必要的读取。所有者可在网页只读浏览、预览、下载该 Agent 的默认工作目录；节点离线时显示不可用。网页浏览路径和符号链接不能越过所选工作目录。 |
| 执行 | Agent 命令作为当前普通账号的子进程运行，返回输出与退出状态，无 Mate 逐条审批。Agent 要用 root 时可在命令中写 `sudo`；宿主已有 sudo 规则决定是否成功。Mate 不另设提权 broker 或审批卡，不保证普通账号能终止 sudo 派生的 root 进程。 |
| 连续性 | 每个 Agent 在频道、讨论串和私信之间共享一个逻辑 session，至多有一条获授权的主 run。控制面在进程内推进循环，每条模型会话记录持久确认后才继续；新 run 和重启从同一会话记录恢复，不 fork 上下文。运行成功可把本轮覆盖的消息投递标为已处理，即使没有公开回复；这不完成任务。所属节点离线或停止时，整个 Agent run 停止推进，包括控制面工具；节点恢复后沿用原身份与 session，人工暂停仍有效。旧 run 失去提交资格，重连从已确认记录恢复；本地命令的操作收据用于核对，未知副作用不得盲目重放。 |
| 失败与诊断 | 暂时的模型服务失败自动退避，人工暂停与凭据错误等待处理。原 Agent 身份、会话与执行环境可用时，历史操作结果未知不阻止后续工作，不要求人类确认；未知事实在后续模型决策前持久提供给 Agent，由其决定检查、补救或继续，恢复程序不自动重放未知操作。活动页展示控制面确认的 run 和操作事实、断连与迟到收据；默认显示安全摘要，详情由所有者展开。 |
| 网页与通知 | 桌面三栏、手机逐层导航；消息操作通过悬停、键盘聚焦或触屏菜单出现。PWA 与 Web Push 提醒 Agent 发给所有者的私信和 @所有者消息。通知失败不撤销已提交消息。 |

Agent 从已有消息创建任务时，控制面提供该消息上已存在或并发新增的关联任务事实，由模型决定认领、协调、放弃或另建。对新增关联任务的检查与创建在同一短事务中提交，模型思考在事务外进行；只修改既有任务的标题、负责人或状态不触发这道新增任务检查。消息正文变化仍由现有草稿流程处理；两类提交前提满足后才创建任务。所有者通过网页直接创建任务不增加模型审核或额外确认步骤。

## 架构责任

| 边界 | 持有与执行 |
|---|---|
| 控制面 | 唯一共享权威：成员与对话、任务、提醒、注意力、会话记录、动作账本、模型凭据、调度和活动事件；提供网页、API、实时事件和通知。它在自身进程内推进 Agent 模型与工具循环，直接构造上下文、请求模型、确认 transcript、压缩、提示忙中消息和恢复 session。它统一路由与授权工具请求，控制面工具直接执行，本机工具交所属节点，并持久记录可产生副作用的操作及结果。 |
| 节点 | 主动连接控制面，在所选 Linux 主机保管默认工作区；以当前账号执行文件操作、普通命令和进程控制，持久保存本地操作收据并在重连时交回。节点不请求模型、不推进 Agent session，也不拥有 run 的调度或完成状态。 |
| 模型 | 决定相关性、贡献、任务组织、暂缓和沉默、记忆内容。控制面使用 `@earendil-works/pi-agent-core` 与 `@earendil-works/pi-ai` 直接异步调用模型；凭据仅在控制面使用。控制面与节点同账号下不承诺凭据的操作系统级隔离。 |
| 浏览器 | 中文网页、密码与会话 cookie、对话和管理界面。浏览器显示持久事实，不成为权限或持久状态的唯一来源。 |

控制面直接等待完整会话记录的持久提交，不再通过节点传输上下文、请求 transcript 确认或回报模型 run 完成。控制面根据同一 current run 事实拒绝旧模型输出和工具行动；异步工具在等待后继续派发新本机请求或提交新的可见副作用前仍须检查资格。控制面与节点按操作 ID、请求内容、收据和重连协议核对已有本机执行；失效 run 的操作收据仍可登记，但不能继续其工作流。节点收据是执行证据，不是会话或调度库；不为模型搬迁强制改换存储介质。控制面或节点离线时 Agent 循环停止；已启动的本地命令可能继续，结果在重连后核对。模型服务级 API key 由控制面保存并直接用于 provider 请求，不下发节点；首版仅支持 API key，不支持订阅账号 OAuth。

首版使用私有控制面镜像/Compose 与普通账号 node 安装包和用户服务，HTTPS 由宿主已有代理提供。通用下载、版本选择、配置处理与 Linux 目录/服务管理分开，不实现其他平台或部署平台。程序、配置和数据分置；同一发布版本手动升级保留原数据、身份、会话与工作区，卸载仅移除 Mate 程序/用户单元。用户明确自行配置 linger；Mate 不提供自动升级/回滚、数据清除、发布登记或维护期协调备份恢复。安装、更新与卸载步骤见[运维说明](OPERATIONS.md)。日常会话持久化、断连重连、节点收据和重启接续继续保留；历史操作未知不阻止后续工作、不自动重放，也不解除人工暂停。身份、会话或执行环境实际不可用时报告具体原因，由所有者修复原数据与环境。远程节点提供配对和故障排查说明。

## 验收原则

以合成消息和脚本化模型服务，运行真实控制面内的 Pi 循环、WebSocket、节点、控制面持久库和本地操作收据，覆盖对话替代选择、显式发言与静默、单 Agent 不并发、会话不分叉、忙中消息、压缩、创建与停用、离线全停、断连、重启、收据对账和未知结果。浏览器检查桌面、手机与讨论串。真实模型服务检查只验证传输和协议兼容，不评测自主行为。

Mate 通过自己的网页和后端接口提供控制面，不支持 Slack、外部平台历史/回显对账或本地 JSONL 控制台。旧单进程运行时、配置、测试与运维入口已移除；ADR-0002 允许重设旧配置、数据库和接口而不提供迁移。Raft 材料仅供产品交互参考，不要求复制其私人数据、集成或运行时。
