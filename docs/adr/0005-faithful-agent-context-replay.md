# 完整保存模型上下文并保持历史前缀

Agent 在频道、讨论串和私信之间延续同一条会话，需要从持久记录完整恢复模型已经经历的有序上下文。固定模型与配置、没有压缩时，后续上下文只在尾部追加；换对话位置、开始新一轮运行和进程重启都不改写已有前缀。根据消息投递、任务或运行的最新状态重新拼装历史，以及把工具交互改写成业务摘要，不能代替完整会话记录。

会话记录以 Pi 消息结构为基础，完整保留重放所需的内容块、工具调用关联和模型协议字段，避免另造一套有损的文本转换；保留供应商返回的 token 用量与缓存数据，供后端接口统计该 Agent 的使用情况。统计是记录的观察结果，不用于用量额度或停止运行的判断。此次重构同时检查所有相关业务表，移除无用记录和对同一事实的重复维护，不限于修改会话表；模型曾经看到的内容与后来变化的业务状态分别承担历史观测和当前状态的职责，不能以去重为由用当前状态替换历史输入。

控制面的 SQLite 是会话记录的唯一持久来源，按顺序保存完整消息与必要的归属信息，压缩也追加记录；不另维护一份 JSONL 权威日志。以完整消息为持久提交单位，不逐段保存未完成的流式输出，也不把这些片段作为完整历史重放。完整工具调用先持久化再执行，工具结果持久化后才开始下一次模型请求；已经执行的操作仍通过持久操作身份和收据核对，恢复不能重新执行已完成或结果未知的副作用。

Agent 配置修改从下一轮运行生效，并记录该轮采用的配置；有意修改模型、系统提示或工具定义所造成的前缀变化属于允许的边界。普通频道切换、消息到达和运行状态变化不构成配置变化。前缀稳定在实际模型请求的内容与顺序上验证，不以数据库记录相同代替；提示模板、工具定义和模型适配版本的更新也需计入采用的配置。

此约束用于保证上下文连续性和供应商缓存可复用的前提，不承诺供应商端的缓存永不失效。重做存储的目标是让内部记录结构和恢复逻辑直观、可维护，不增加会话查看界面或要求磁盘文件直接可读。本轮业务表整理不新增历史记录清理机制，不按记录年龄、数量或磁盘占用删除历史，保留完整会话与恢复证据。

所有者通过后端接口查看 Agent 的累计 token 用量和缓存命中率，以及最近一次普通模型请求的统计。累计值包含生成压缩摘要的请求，同时分别提供普通请求和摘要请求的统计，跨频道、重启和压缩不清零。缓存命中率采用累计缓存读取 token 除以累计全部输入 token，后者包含未缓存输入、缓存读取与缓存写入；不平均各次请求的百分比，也不把输出 token 算入分母。供应商未报告的数据不能冒充零命中，接口说明可用数据的范围。

完整行为与验收见[经独立设计审查的规格 #105](https://github.com/yy4382/mate/issues/105)。
