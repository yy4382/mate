# 有限 Linux 包装：容器控制面与用户服务节点

所有者现在需要可直接使用的轻量安装产物，不能在低资源 VPS 上自行编译和拼装依赖。首版采用私有控制面镜像与仅含控制面的 Compose，以及内带专用 Node 和预编译依赖的 Linux node 包；node 安装在现有普通账号的用户目录，由该账号的 systemd 用户服务运行，控制面容器使用同一宿主 UID/GID。验收 Ubuntu 24.04、Debian 13 的 x86_64/arm64；下载与版本配置逻辑和 Linux 路径/服务操作分开，仅留结构扩展位置，不实现其他平台或部署管理平台。

本决定有限替代 ADR-0008 对部署工具的全面排除，以及 ADR-0003/0004 的整体 systemd 禁令。安装器不安装系统软件、不创建账号或切换身份、不修改 sudo/Docker 权限或 linger，不把 Agent 命令包进 systemd 单元；用户自行决定 linger 与 HTTPS 代理。程序、配置、数据分置，手动以同一发布版本更换控制面和 node，保留原身份、会话、数据与工作区；卸载仅删除 Mate 程序和用户单元。不恢复发布登记、自动升级/回滚、数据清除、协调备份恢复、维护对账或人工释放。

这是已确认的发布目标，实施规格见 [#131](https://github.com/yy4382/mate/issues/131)，尚未实现或安装验收。实际镜像与 node 发布包联通、真实 Linux 宿主或 VM 上的用户服务生命周期是两个验收接缝；容器成功不能替代 systemd 用户安装证据。控制面继续拥有模型循环、凭据和唯一 session，node 继续只提供执行环境；既有日常恢复语义不因包装改变。
