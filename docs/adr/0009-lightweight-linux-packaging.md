# 有限 Linux 包装：容器控制面与 CLI 管理的用户服务节点

所有者需要可直接使用的轻量安装产物，不能在低资源 VPS 上自行编译和拼装依赖。首版采用私有控制面镜像与仅含控制面的 Compose，以及同版管理 CLI、专用 Node、node 程序和预编译依赖组成的完整 Linux 包。薄 shell bootstrap 仅获取、校验并通过包内运行时安装统一 `mate` 入口；`mate node` CLI 负责 node 安装、systemd 用户服务管理、启停、状态、日志、显式更新与卸载，避免 shell 承担管理逻辑。node 在现有普通账号的用户目录与用户服务中运行，控制面容器使用同一宿主 UID/GID；验收 Ubuntu 24.04、Debian 13 的 x86_64/arm64。CLI 中通用下载、版本、配置逻辑与 Linux 路径/服务边界分开，不实现其他平台或部署管理平台。

本决定有限替代 ADR-0008 对部署工具的全面排除，以及 ADR-0003/0004 的整体 systemd 禁令。bootstrap 不操作服务或修改 shell 配置；CLI 不安装系统软件、不创建账号或切换身份、不修改 sudo/Docker 权限或 linger，不把 Agent 命令包进 systemd 单元。用户自行决定 linger 与 HTTPS 代理。程序、配置、数据分置，手动停机后以同一发布版本更换控制面及完整 node 包，包含 CLI 自身与专用 Node，更新后保持停止；保留原身份、会话、数据与工作区。卸载仅删除 Mate 程序和用户单元，失败或中断可从本地发布包重试。不恢复发布登记、自动更新/回滚、数据清除、协调备份恢复、维护对账或人工释放。

这是已确认的发布目标，实施规格见 [#131](https://github.com/yy4382/mate/issues/131)，实现及实际验收边界见 [部署验收](../DEPLOYMENT_ACCEPTANCE.md)或安装验收。实际镜像与 node 发布包联通、薄 bootstrap → 包内 CLI → 真实 Linux 宿主或 VM 用户服务生命周期是两个验收接缝；后者覆盖整包及 CLI 自身更新、切换前失败保留旧入口和数据、切换后中断按实际安装事实恢复、缺失 user manager 的明确错误，容器成功不能替代此证据。控制面继续拥有模型循环、凭据和唯一 session，node 继续只提供执行环境；既有日常恢复语义不因包装改变。
