# 运行时按 Pi 的方法自动压缩上下文

持久工作的 Agent 需要在模型上下文容量有限时继续运行。由运行时根据上下文容量触发压缩并调用模型生成摘要，移除由工作中的 Agent 自行调用的 `session.compact` 工具。采用 [pi-coding-agent v0.86.0 的压缩方法](https://github.com/earendil-works/pi/blob/v0.86.0/packages/coding-agent/docs/compaction.md)，在 Mate 使用的 `pi-agent-core` 与 `pi-ai` 之上实现；不以 `pi-coding-agent` 替换 Mate 运行时。

具体沿用其容量预留与近期消息保留策略、按消息边界切分、长轮次前半段单独总结、把前次摘要纳入后续总结，以及追加包含摘要和首条保留记录位置的压缩记录。工具调用与结果保持关联，后续上下文由摘要和保留的消息重建；摘要生成所用的临时文本处理不修改原始会话记录。压缩结果经控制面持久确认后才生效，失败或中断不切换到未提交的摘要。Agent 的逻辑会话保持连续，压缩是允许改变上下文前缀的明确边界。

摘要请求也直接沿用 Pi 的方法：使用专用摘要系统提示，将选中历史序列化为文本，不提供工作工具，采用 `cacheRetention: "none"` 和独立摘要路由。其目的是让模型把历史当作总结材料，避免继续执行原任务；一次性摘要不额外建立可复用缓存。这里的独立请求不创建第二条 Agent 逻辑会话。普通续接保持前缀稳定，但摘要请求及压缩后的首次普通请求不保证复用旧历史缓存。

摘要用的文本转换、工具结果截断和临时指令不改变原始会话记录。摘要覆盖与保留起点一起确定，不遗漏既未纳入总结材料、又未保留的消息；摘要不执行工具，意外工具调用、截断或错误不能成为成功压缩结果。普通请求与摘要请求都计入总体用量，并分别可查。取舍依据见[研究记录](../research/pi-compaction-cache.md)。

只移植压缩所需方法，适配 Mate 的消息与工具结构、控制面持久确认和故障恢复；不引入 Pi 的会话分支或其他无关 coding-agent 功能。上下文容量估算用于判断是否需要压缩，不是模型使用额度；token 用量与缓存统计仅用于观察。
