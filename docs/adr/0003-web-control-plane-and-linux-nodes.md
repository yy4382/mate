# 以网页控制面和 Linux 节点取代 Slack 单进程部署

Mate 的所有者需要在一个地方交流、查看任务和运行状态，也需要让不同机器上的 Agent 使用各自机器的文件和命令。Slack 的历史、回显、权限与界面边界使这些交互依赖外部平台；单一守护进程也无法清楚表达跨机器的执行位置。因此，首版以 Mate 自己的中文网页作为操作界面，并拆成一个控制面与一个或多个 Linux 节点。

控制面保存共享事实、完整模型会话记录和动作账本，负责调度、工具路由与网页。节点主动连接控制面，运行模型子进程和本机操作，保管 Agent 的默认工作区与操作收据。控制面、节点、模型进程和 Agent 命令在同一台主机上使用同一个现有的非 root 账号；Agent 的命令是普通子进程，若命令显式调用 `sudo`，结果只取决于宿主权限。Mate 不创建账号、不切换身份、不管理 systemd。断连时旧 run 放弃，从控制面已确认的会话记录恢复；已启动的本机操作按操作 ID 和节点收据核对，结果未知时不盲目重放。

首版验收同一台低资源 Linux VPS 上两个同账号普通进程、HTTPS、命令执行和协调备份恢复。远程 Linux 节点可以手动配对，但跨机部署不作为首版验收。首版不支持 Slack 操作路径、旧数据迁移或 Agent 跨节点迁移。旧实现、配置、测试和运维入口不长期保留两套运行方式。

完整目标行为与验收边界见 [产品方向](../PROJECT_DIRECTION.md)和[经设计审查的规格](https://github.com/yy4382/mate/issues/70)；单账号执行原因见 [ADR-0004](0004-single-account-command-execution.md)，首版兼容性取舍见 [ADR-0002](0002-first-release-compatibility-reset.md)。
