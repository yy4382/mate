# Node 与 palace node CLI 边界测试

> 这个模块的设计见同目录的 [ARCHITECTURE.md](ARCHITECTURE.md)。所有模块共用的测试规则和替身见 [docs/MODULE_TESTS.md](../../docs/MODULE_TESTS.md)。

## 1. Node

**边界：** node 进程对网关说的 WebSocket 协议，以及它在文件系统和进程上的实际效果。测试在 Linux、macOS、Windows 上运行。`pnpm test:linux` 在 Linux 容器里以非 root 账号运行；CI 另外在 `macos-latest`、`windows-latest` 运行 node 套件，并汇入 `checks`。正常关闭通过 `startNode` 的 AbortSignal 验证。

**替身：** 假网关。

- node 每次认证和配对都报告宿主平台、架构、hostname、系统版本和程序版本。源码运行报告 `dev`。

### 1.1 命令

- 命令交给所在平台的 shell：Linux/macOS 为账号配置的 Bash/zsh（不看可变的 SHELL），Windows 为 PowerShell 5.1。首次命令在该 Agent 的工作目录；HOME 在 Linux/macOS 是账号主目录，在 Windows 是工作目录。Windows 也验证 `$HOME`、原生程序的退出码和后续成功命令不沿用旧失败码。
- `visit` 准备 Agent 的工作区，不初始化 MEMORY.md，`home` 使用已有主工作区；两者共用上面的初始目录和 HOME 规则。Windows 在 node 没有 HOME 时也设置 PowerShell 的 `$HOME`。
- 启动文件设置的变量、数组、只读值、导出、别名、函数（含 zsh 的 fpath 自动加载和模块）和选项在每条命令里可用；终端和启动文件相关的选项不恢复。启动文件的输出不混进命令输出，每个 node 进程只执行一次，之后的修改和命令里的改动都不影响快照；BASH_ENV/ENV 不会被执行。超过 4 MiB 的快照失败且不执行命令；失败保留到 node 重启。
- 停止等待捕获的调用不影响其他调用，也不让捕获失败；之后的调用照常使用快照。
- 前台命令的 cd 对同一对话的下一条命令生效，非零退出也算；路径里的空白和换行保留，输出重定向和占着描述符的后台进程不妨碍记录。exit、exec、信号让目录保持不变，结果不变。同时进行的前台命令中最后结束的决定目录。后台命令从记住的目录开始但不改它；不同对话、不同 Agent 互不影响；node 重连保留，重启从工作区开始。记住的目录被删时从工作区开始并说明；缺少工作区时仍要求重新准备。
- POSIX 上 Agent 自己写的 `sudo` 原样执行，成败由宿主决定；node 从不自己加提权命令。
- 三个平台都验证正常退出与 shell 退出码、超时、停止、没能启动（例如命令含 NUL）。POSIX 另外验证被信号终止。
- 输出超过上限时截断，并在结果里标明。
- `timeout` 超过协议规定的、这个模式的上限时（前台 1 小时，后台一天），命令不执行，返回参数错误；后台命令可以要超过 1 小时的时限。
- 命令退出后，后台子进程仍占着输出管道：node 不会一直等下去，在短暂等待后返回，并标明输出可能不完整。
- Linux 进程组里只剩僵尸进程时，算作已经结束。
- Windows 的终止命令失败时，调用及时返回明确错误，不声称已经停止；恢复终止能力后，node 正常关闭仍能清理该进程树；根进程已退出时不误报终止失败。
- Linux 上 PID 被复用后，停止旧命令不会误杀新进程。

### 1.2 文件

- 文件工具（`read`、`write`、`edit`）的行为与 Durable 自带工具在本地执行时一致。
- `visit` 的三种文件工具和 bash 共用 Agent 工作区。首次调用准备目录；相对路径和工作区内绝对路径指向相同文件，工作区外文件的写入被拒绝。两个 Agent 在同一 node 上写同名文件，分别读到自己的内容。
- 以两个点开头的普通文件名（`..notes.md`、`..cache/x.txt`）照常读写。POSIX 上单独的 `...` 也是普通名字。
- 路径不能逃出工作目录：`..`、指向工作目录外的绝对路径、指向外部的符号链接都被拒绝。（Durable 的文件工具内部会把路径先变成绝对路径再解析，所以指向工作目录内的绝对路径照常可用。）
- Windows 接受根目录的 junction、短名和大小写别名，拒绝越界路径和根以下的链接。

### 1.3 连接与停止

- 连接断开时，正在运行的、由工具调用启动的进程组被停止。
- 网关停止一次调用，只杀掉这次调用的进程组，同一个 Agent 和其他 Agent 的其他调用照常运行；停止 `visit` 调用时，同一 Agent 的 `home` 调用也不受影响。
- POSIX 命令已经返回、后台进程还占着输出时收到停止，后台进程也被杀掉。Windows 只保证 shell 仍存活时的进程树。
- 通过真实网关：调用方中止调用后，node 上这次调用的进程组消失，调用方得到"已停止"；另一个 Agent 的并发调用不受影响，拿到自己的结果。
- 三个平台都证明 node 正常关闭时清理仍在运行的命令。POSIX 还检查命令已经返回的后台进程组。
- 修改或删除工作目录里的 `MEMORY.md`，不影响之后的命令执行。
- 主工作目录不存在时，所有工具报错且不重建。显式准备主工作区会创建缺失的空 MEMORY.md，已有文件不覆盖。访问工作区在显式准备和执行前准备时均不初始化 MEMORY.md。工作区路径是普通文件时访问工具失败，移除冲突后重试成功。重复准备及重连保留已有文件；远端用户自行创建再删除的 MEMORY.md 不会补写。
- 运行中的 node 握手成功后，`palace node status`（假服务管理器报告这个真实子进程的身份）显示 `Link: connected since <时间>`；网关消失后显示 `Link: disconnected since <时间>`。网关连不上时从启动起就是 `disconnected`。
- 身份被拒绝时，node 退出，退出码是用户服务不会重启的那个（§2），不会无限重试；网络失败或网关以协议错误（例如握手超时）结束连接时，按退避重连。

### 1.4 浏览工作区

- 目录按名字列出条目，文件带大小。POSIX 上指向工作目录内的符号链接列为符号链接，经它浏览照常可用；Windows 拒绝经过符号链接或 junction。指向工作目录内的绝对路径照常可用；以两个点开头的名字是普通名字。
- 文件返回开头的文字；超过上限时只返回上限以内、截在完整字符处的部分并标明截断。条目超过上限的目录同样只返回上限条并标明截断。含 NUL 字节的文件只报告大小。
- 路径不能逃出工作目录：`..`、指向工作目录外的绝对路径、指向外部的符号链接（目录或文件）、悬空的符号链接都以 `outside-workspace` 拒绝；浏览前后工作目录内外都没有变化。
- 不存在的路径、工作目录不存在时以 `not-found` 拒绝，node 不重建工作目录；FIFO 以 `unreadable` 拒绝，不会一直等写入方。
- 经真实网关：浏览能列出和读取真实工作区，拒绝指向外部的符号链接；node 停下后回答 `node-offline`。

## 2. Node 管理 CLI

**边界：** `palace node` 命令行，以及它读的发布包和它留在 HOME 里的文件（布局见 [DEPLOYMENT §3.2](../../docs/DEPLOYMENT.md)）。测试以子进程运行 CLI，不 import 它的内部文件。

**替身：** CLI 通过宿主平台的假服务命令观察系统状态：Linux 的 systemctl/journalctl、macOS 的 launchctl、Windows 的 schtasks 与结构化任务查询。它们记录操作并按服务定义和测试状态回答。配置、身份和程序都放在临时账号目录（Windows 同时设置 USERPROFILE 和 LOCALAPPDATA）；测试自己写同格式的发布包。所有断言经过公开 CLI，不能直接测试平台适配器私有函数。

**没有可续做的状态机（见 [ARCHITECTURE.md](ARCHITECTURE.md) 的"服务与退出"）。** 每个命令只看现有状态：程序目录（不存在 / Palace 的某个版本 / 没有清单，不是 Palace 的）、`palace` 命令和服务定义（不存在 / Palace 的 / 别人的）、服务状态。所以"中断后重跑"的测试构造的是中断可能留下的状态（程序目录已挪开但新的还没放好、半个暂存目录、单元已删程序还在），再加一个在解包中途真的 SIGKILL 的测试。

- 首次 `install` 放好程序目录、`palace` 命令和单元文件，不启用也不启动服务；`start` 之后服务被启用并运行。没有配置时 `start` 拒绝。
- 重复 `install` 保留程序，不启动、重启或启用服务；Windows 停止任务的定义重新注册，更新过的服务参数会生效。
- 已装了另一个版本时 `install` 拒绝（提示用 `update`），不做任何改动。
- `update` 在服务运行、正在启动或停止、等待重启、状态不明时拒绝。Windows 的任务仍启用、可能再次触发时也拒绝。
- `update` 在服务停止时换上新版本，服务保持停止；配置、身份、工作区逐字节不变。
- `update` 死在"旧程序目录已挪开、新的还没放好"之间，或留下半个暂存目录，重跑同一个命令完成更新，不留下暂存目录。
- `update` 在校验或解包发布包时被 SIGKILL，已装的程序目录原样不变；重跑完成更新。
- `uninstall` 停用并停止服务，删除程序目录、`palace` 命令和单元文件，保留配置、身份和工作区；再跑一次报告没有可删的东西，不改动任何文件。
- `uninstall` 死在"单元已删"或"删程序目录到一半"之后，重跑完成卸载。
- 程序目录里有 Palace 没装的文件或目录时，`update` 和 `uninstall` 拒绝，列出它们，不做任何改动；`status` 也报告它们。
- 不是 Palace 写的服务定义和命令，`install` 和 `uninstall` 都不碰，并在输出里报告；`uninstall` 对这样的单元定义的服务也只读状态，不停用它。
- 发布包校验和不对、缺 `.sha256`、含符号链接、硬链接、特殊文件、含 `..` 的路径、绝对路径、`palace-node/` 之外的路径、清单没列的文件、缺清单列的文件、平台或架构不匹配时，拒绝；已安装的东西不变，首次安装不留下任何文件。
- 没有用户管理器时，`install`、`update`、`uninstall` 拒绝，不做任何改动。
- 管理命令以 root 运行时拒绝（Linux 上用 `unshare -r` 得到 UID 0）。`node run` 不检查，它只由用户服务启动。
- `configure` 在 POSIX 写出权限 0600 的配置，Windows 写在账号的 LOCALAPPDATA 下，不用 mode 位冒充 ACL 检查。不带 `--pairing-token` 再写一次就去掉令牌；地址不是 http(s)/ws(s) 时拒绝，原文件不变。
- `status` 报告版本、服务状态和配置，不打印配对令牌。
- `status` 的 `Link:` 行只在服务运行且能确认 `link.json` 属于该服务进程时读它；否则是 `Link: none`。
- `logs` 读这个服务的用户日志，`--follow` 时跟随。
- 没有配置或身份被拒绝时，前台 `node run` 返回 78。Linux 服务保留 78 并配置不重启；macOS 的 `--service` 入口把它映射为 0，实际服务不会反复重启，并保留原因日志。

发布构建下载固定校验和的官方 Node，默认产出 Linux x64、macOS arm64、Windows x64 三个包。Linux 容器、macOS/Windows CI 用真实发布包验证安装、配置、启停、链路和不可重试退出，并验证 Windows 崩溃后手动启动能恢复；从已安装命令更新和卸载。开发机不自动安装真实服务。
