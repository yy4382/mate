# 网页客户端（`@palace/web`）

> 总览见 [docs/ARCHITECTURE.md](../../docs/ARCHITECTURE.md)。外观和交互规则见 [DESIGN.md](../../docs/DESIGN.md)。后端见 [apps/control-plane/ARCHITECTURE.md](../control-plane/ARCHITECTURE.md)。测试见 [TESTS.md](TESTS.md)。

## 结构

一个网页应用挂两个功能区：聊天和管理。它们是两个互不 import 的前端模块（`src/chat`、`src/admin`），只共享外壳（`src/shell`）提供的登录状态、导航和布局。服务端数据统一用 TanStack Query 获取和缓存，页面组件不手写请求和缓存。样式用 Tailwind CSS v4，交互组件用 Base UI，界面原语集中在 `src/shell/ui.tsx`。Vite 构建到 `apps/web/dist`，控制面用 `PALACE_WEB_DIRECTORY` 指向它。

当前人类来自 `GET /api/me`，普通人类看不到管理入口，直接打开管理地址显示"需要管理员权限"。

## 规则

- **账号视图只有一个缓存。** `src/shell/accounts.ts` 持有共享账号查询，聊天快照和实时账号事件写入它，聊天、管理和个人资料都从这里读。头像上传成功后的显示由实时事件推进，不另拉账号快照覆盖较新的事件。浏览器把图片居中裁剪、缩到最多 256px 的 PNG 再上传。

- **每条时间线一个查询，条目按序号存放。** 重复或重放的实时事件落在同一个序号上，不会多出一条消息，也不会让讨论串的回复数虚增（回复数是已见回复序号的集合）。实时事件只更新已有的时间线查询；第一页还在加载时到达的条目先暂存，页面到达后并进去。

- **会话在事件流之前确定。** 先按地址里的会话拉快照，用它填缓存，再从快照的游标起开事件流。`resnapshot` 清掉聊天缓存、重新拉快照后重连。`login` 和任何 API 的 401 都跳到 `/login?next=`。

- **发送带客户端生成的 `requestId`，失败重试沿用同一个。** 草稿和未完成的发送放在页面之外的模块里，切换会话也不丢。发送成功只去掉已发送的那部分文字，发送期间又输入的文字保留。4xx 拒绝说明什么都没发生，下一次发送是新请求。

- **看到就是读过。** 打开的时间线有未读时，页面对每个最新序号报一次 `POST read`。

- **管理操作按 node ID 提交，显示用名字。** 授权、收回和改名都独立于模型设置表单，成功后刷新 node 和 Agent 查询。

- **webhook 密钥只显示一次。** 创建或轮换成功后，密钥和带真实密钥的 curl 只在随后的对话框里出现一次。列表里的 curl 用 `$WEBHOOK_SECRET` 占位。地址和 curl 由 `@palace/admin/client` 的 `webhookUrl`、`webhookCurl` 生成，移动端用同一份。

- **推送订阅随登录走。** 开启通知时注册 `sw.js`，用 VAPID 公钥订阅再登记。退出登录时先取消这个浏览器的订阅，失败也照常退出，所以下一个登录的人收不到上一个人的通知；服务端另有保底，见聊天规则 8。点开通知进入 `/app/c/:会话[/t/:讨论串]?seq=N`，那条消息不在时回到最新并提示。

## 本地化

`src/locales/{zh,en}.json` 按功能保存文案，i18next 处理插值和复数，日期、数字和列表用匹配语言的 Intl。首次渲染前按 `navigator.languages` 的顺序匹配：`zh` 变体用简体中文，`en` 变体用英文，否则英文，并同步文档 `lang`。不读 URL、cookie 或本地存储里的语言覆盖，没有语言选择器。错误码和枚举只在视图里映射显示名，用户和 Agent 的内容原样显示。构建同时生成本地化的 PWA manifest 和独立的 classic `sw.js`，通知用同一份资源和语言检测。

## 已知的后端缺口

前端因此降级：历史条目不带回复数，所以讨论串回复数只统计本次页面见过的回复；搜索结果不带会话和时间线，不能点进去；没有列出任务的接口，任务只在所属消息和时间线上显示。
