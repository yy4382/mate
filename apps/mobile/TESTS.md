# 移动客户端边界测试

> 这个模块的设计见同目录的 [ARCHITECTURE.md](ARCHITECTURE.md)。所有模块共用的测试规则和替身见 [docs/MODULE_TESTS.md](../../docs/MODULE_TESTS.md)。

## 1. 原生移动认证

**边界：** `MobileAuth` 的公开操作与状态订阅。`apps/mobile/test/auth.test.ts` 替换外部原生网络、cookie 存储和设置存储，不替换认证模块内部逻辑；测试不声称覆盖 iOS 的 cookie 持久化。

- 只保存一个不含账号或路径的 HTTPS origin；拒绝不合法地址时不联系服务器。
- handle 和密码只提交一次，从 `/api/me` 获取身份；设置里保存验证过的身份，没有密码。
- 密码不对与连接失败分别显示，失败后可重试。
- 启动恢复时先发布最近验证的身份并重新验证 cookie，读不出的保存身份按未保存处理；连接失败保留重试资格；401 结束登录，重启后不再显示该身份。
- 离线退出先禁止恢复，再尝试撤销，清理原生 cookie，并提示撤销未确认；重启不自动恢复。
- 换地址先在旧服务器撤销仍可能存在的会话，再清理原生 cookie，不向新地址发请求；离线时提示撤销未确认，没有会话时不联系旧服务器。
- 退出或换地址后，旧登录与身份响应不能重新显示身份；再次登录前旧请求已结束、cookie 已清理。切回原地址也不恢复旧身份。

**原生验证。** 使用独占的普通 iPhone iOS 27 模拟器和临时 HTTPS 控制面，驱动 app 界面验证正确与错误密码、正常使用后的重启恢复、前台重验、过期或撤销的 401、离线重试、在线与离线退出后重启，以及切换服务器的身份与凭据隔离。截图检查浅色、暗色、Dynamic Type 和键盘操作。该验证不作为永久 smoke 测试提交，也不承诺立即强杀进程后的 cookie 持久化。

## 2. 原生聊天

**边界：** `MobileChat` 的公开操作与状态订阅。网络和时钟属于外部依赖；测试通过真实 `ChatApp` 的公开接口准备数据与处理请求，不替换聊天客户端内部逻辑。

- 发送响应丢失后沿用原请求 ID 重试，服务端只出现一条消息；发送期间新增文字保留。
- 快照取得后即使原生事件流的连接仍等待响应，也能读历史、定位与发送，连接完成后继续接收实时数据。
- 历史加载期间的实时消息合并，重复事件不重复显示；CRLF 和中文 UTF-8 字符跨网络 chunk 时仍正确接收；实时会话更新和重复打开私信原位替换，会话保持服务端顺序。
- 频道和讨论串草稿相互独立；读取历史与搜索不推进已读，显式阅读推进已读。
- 历史读取失败后重复自动加载不会继续请求，显式重试恢复；频道和讨论串的旧目标能通过分页定位；取消一个定位不中止同一时间线上另一个定位共用的翻页读取。
- 未确认的任务、频道创建和成员操作跨界面关闭保留输入和请求 ID，重复提交只生效一次，未确认期间不发出另一份输入；确认完成或明确拒绝后释放，退出登录清空。Agent 私信使用选定的聊天账号，丢响应重试及再次打开返回同一个会话。
- 重连从最后一个已应用游标继续，断线期间的消息补齐；事件流没有心跳时重新连接。
- 游标失效后重取快照并保留草稿；旧快照所属的迟到历史不写进新状态。
- 退出或切换身份后，迟到的快照、历史和发送结果不重新填入旧数据；草稿清空。
- 持有者启动前和暂停期间不发任何请求：发送等待启动后才送出，人为重连不打破暂停，身份关闭时等待中的发送不送出。
- 服务端的 `login` 事件交给认证模块重新验证。

**原生验证。** 在独占普通 iPhone iOS 27 模拟器上构建正常 Expo app，连接一次性本地 HTTPS 控制面。第二个人类客户端通过 HTTP 发送，验证原生界面的发送、实时接收、讨论串、未读、搜索、提及、任务、长按消息菜单（回复、复制、创建任务）、「回到最新消息」按钮与未读角标、断线时标题旁的转圈、退出和切换服务器隔离。截图检查浅色、暗色、Dynamic Type 与键盘。临时 UI 驱动和服务夹具只作为本次验证产物，不加入永久 smoke 测试。
## 3. 原生管理与个人资料

**边界。** `ManagementClient` 的访问状态订阅、请求、保存资料、观察和关闭接口，以及它订阅的 `MobileAuth` 状态。测试只替换外部网络与本机认证存储，通过公开响应和请求判断结果，不导入 reducer 或界面内部逻辑。`management-http.test.ts` 通过真实控制面的 HTTP 接口验证前台重验取消响应后的同 ID 重试（包括服务器已完成创建时的确认）、恢复确认期间 Agent 被删除时不报告成功、资料持久性和修改密码后当前 cookie 继续有效；拒绝码和中断创建本身由控制面的 `refusals.test.ts` 覆盖。

- 请求发给选中的服务器并携带 cookie，写操作使用 JSON，204 视为成功；403、409 和创建中断的 Agent ID 原样交给调用方。
- 资料保存立即更新当前身份，不清理 cookie，不取消同一登录下的其他请求；保存被拒绝时身份不变。
- 退出或更换服务器后，迟到的资料、管理数据和观察批次不再交付；旧请求迟到的 401 也不能重新验证另一个人类的登录。
- 前台重验与网络故障暂停管理访问，相同服务器、账号和角色验证成功后恢复请求；重验前的迟到响应与 401 即使在恢复后也不能交付。账号或角色变化关闭旧访问并清除旧身份。
- 当前登录收到 401 时重新验证，确认失效则关闭管理访问；网络失败不能报告保存成功，交出的错误不是服务器拒绝，界面显示连接问题。
- 观察接收分片 UTF-8 和 SSE 批次，支持工作助手参数，以 `ended` 结束；断线同样显示为连接问题，已关闭的登录不再收到事件。

原生界面验证使用独占的普通 iPhone iOS 27 模拟器、临时 HTTPS 控制面、公开的 FakeNode 和 ScriptedProvider。通过真实表单验证管理读写、角色限制、Agent 观察与工作区、个人资料和密码持久性，以及浅色、暗色、大字体与键盘。创建中断后通过原生 Back、重新打开和返回首页验证草稿与恢复 ID 保留，修复 Node 后从界面继续创建成功；列表保留完成回执，下一次创建开始新草稿。退出或换账号后没有旧草稿。创建响应被扣留时前台往返仍使用发送前的 ID 继续创建；选择器和危险操作确认页在扣留认证响应时隐藏且无法点击，相同身份重验后恢复，401 后清除。前台往返验证相同账号保留当前页面和未保存草稿，失效登录、退出、服务器和账号变化清除旧页面与数据。截图和执行日志留在临时目录，驱动脚本不作为永久 smoke 测试提交。

生命周期整合由 `lifecycle.test.ts` 驱动 `startMobileLifecycle`、真实 `MobileAuth` 与 `MobileNotifications` 的公开接口，替换外部 AppState、权限、网络和聊天实例；通知会话只来自认证状态，测试不直接设置。权限决定等待时 inactive → active 不增加 `/api/me` 或取消操作；background → active 只验证一次，后台暂停通知和聊天流，验证完成后才恢复；冷启动立即为保存的身份打开聊天，但验证前不运行、不登记通知，验证出另一个账号时关闭未运行的旧实例；资料更新不重新检查通知也不重连聊天；退出关闭这次登录的聊天。原生整合验证从个人资料打开通知设置，操作真实权限弹窗后返回原草稿、完成创建中断后的 Back/重试，并验证退出、401 和服务器切换仍先结束通知会话再改变 cookie。

## 4. 原生通知

原生通知的模块边界由 `apps/mobile/test/notifications.test.ts` 的 `MobileNotifications` 公开操作和状态订阅覆盖。外部替身只替代 iOS 权限、token、设置存储、原生通知展示与网络。测试覆盖未配置、拒绝与撤回权限、token 轮换及取消失败后的重启恢复、多个旧 token 的退出清理、跨服务器与账号的取消责任、迟到取消不能删除新 binding、离线取消、服务器与账号隔离、冷启动和重复点击、过期数据与任意 URL 拒绝，以及认证在在途登记之后取消订阅、再清 cookie 的屏障。轮换恢复测试通过真实 `ChatApp` 的公开接口发送夹具私信，观察恢复后只有当前 token 收到，退出后没有 token 再收到新通知。原生源码和 Node 测试分别类型检查，避免将 Node 全局类型引入原生源码。

通知公开状态同时断言系统权限、服务器能力、登记确认、待取消数量和本机清理结果。订阅应答丢失时保留取消责任，登记必须是「待确认」；系统允许或服务器已配置都不能单独显示登记成功。

`apps/control-plane/test/push.test.ts` 通过真实 HTTP 认证与订阅路由驱动控制面。APNs 是临时 TLS HTTP/2 服务，真实 `@parse/node-apn` 库连接它；只使用现场生成的测试 key，不访问 Apple。服务观察原生 payload、topic、expiry、collapse ID 和错误映射，验证暂时失败重试、失效 token 清理与 provider 错误保留。Web Push 是临时 HTTPS 推送服务，真实 `web-push` 库加密投递给它：404、410 删除订阅，429、5xx 重试，其他状态丢弃这条推送并保留订阅。消息资格和存储夹具测试继续证明共用规则。真实凭据与设备投递不在这些替身测试的结论内。

原生 UI 使用独占的普通 iPhone iOS 27 模拟器、正常 Expo/Xcode 构建和临时 HTTPS 后端。验证允许与拒绝权限、配置缺失、原生收取和点击响应、退出及换服务器隔离，检查浅色、暗色和放大字体。`simctl push` 只注入通知，不证明 APNs 远程投递。驱动脚本和截图只作本地开发证据，不提交为永久 smoke 测试；整合验收通过实际通知子系统收取和点击，检查旧频道/讨论串序号定位及错误账号、服务器和 binding 的拒绝；不把直接深链当成通知验收。
